# 7. Make it yours

Keep model, reasoning and runtime choices in harness-native configuration rather than changing shared method text. Follow the destination's native reference from [Install and setup](01-install-and-setup.md) for its configuration, refresh and loading proof; another harness's commands or pass do not establish that integration.

Keep project terms in `DOMAIN.md`, behavior in `SPEC.md`, consequential decisions beside the code, and local agent constraints in `AGENTS.md`. Say there who owns the code: an agent treats a repository it owns very differently from one it is visiting. Link to this method instead of copying it. Use [agent-design](../../skills/agent-design/SKILL.md) when a project needs a new skill or instruction.

The method is small on purpose. Before adding to it, check the instruction against [agent-design's notes on current models](../../skills/agent-design/SKILL.md#writing-for-current-models), and prefer a check a machine can run. Other skill packs, pstack included, install beside mistystack through your harness; the [exemplars](../exemplars.md) list the sources we draw on. Private workstation configuration and fleet machinery live separately in `misty-step/workstation`.
